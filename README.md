# 财周对照台

连锁零售经营分析员可用本地工作台处理门店财周单，复查配对周差额并与独立清单逐笔核对。

自然日期映射四四五财周，默认只对齐双方营业的同周同星期，孤立第53周单列。提交两年同场促销日期后，工作台改按促销进度对齐（活动第1天对第1天），能看出活动涨跌；一边少办、停业或挪周的日期逐条落单并写明原因，不拿普通营业日补缺，同一天重复登记只计一次。

## 启动

```sh
docker compose up --build
```

打开 http://127.0.0.1:18306 并运行随附样例。可以在「导入来源、促销日期与外部账」上传自己的 CSV，也可以编辑表单中的样例。数据保存于 Compose 卷 `ledger`。使用 `APP_PORT` 可覆盖宿主端口。

## 工作步骤

1. 检查「日销送报」与「财年字段」，定位导入坏行与字段归一结果。
2. 在「日历冲突」区分冲突、业务拒绝、重传与旧版本。
3. 打开「可比财周」并点击任意记录的「查看依据」，查看促销第几天如何配对、哪些日期落单。
4. 在「经营清单」检查金额或用量差异。通过「财周批次」复算原文件（同一批不新增记录），通过「月结复核」提交意见并下载证据；证据里带促销配对与落单原因。

接口定义见 `/openapi.json`。字段、允许区间及算例见 [数据字典](docs/DATA-DICTIONARY.md)，模块和回归测试见 [测试登记](docs/DEPTH.md)。

## 验证

```sh
docker compose config --quiet
docker compose exec -T app pytest -q
```

`sample_data/shift.csv` 是班次数据，`sample_data/promotion.csv` 是两年同场促销日期样例，`sample_data/external.csv` 是独立账样例。`cases.csv` 固定业务反例，`legacy.csv` 和 `truncated.csv` 用于验证历史格式与断行。
